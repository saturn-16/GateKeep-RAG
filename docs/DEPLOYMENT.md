# Deployment Guide: GateKeep RAG

GateKeep RAG is designed for cloud-native deployment with PostgreSQL, Qdrant vector database, and the FastAPI + React unified application.

---

## 1. One-Click Cloud Deployment via Render Blueprints

The repository includes a declarative [`render.yaml`](../render.yaml) blueprint specification that orchestrates:
- **Managed PostgreSQL 16**: Relational storage for tenants, users, roles, documents, chunks, and audit logs.
- **Qdrant Vector Database (Private Service)**: Persistent vector storage with dedicated disk volume (`qdrant-storage`).
- **GateKeep Web Application (Unified Docker Container)**:
  - Multi-stage build producing the optimized React frontend.
  - Automatic Alembic database schema migrations (`alembic upgrade head`).
  - Automatic demo dataset seeding with 11 personas across 3 tenants (`seed_demo.py`).
  - Uvicorn serving both the FastAPI REST endpoints (`/v1/...`) and the interactive React UI at `/`.

### Steps to Deploy on Render

1. **Log in to Render**: Go to [dashboard.render.com](https://dashboard.render.com/).
2. **Create New Blueprint Instance**:
   - In the top-right corner, click **New +** $\rightarrow$ **Blueprint**.
   - Connect your GitHub repository: `https://github.com/saturn-16/GateKeep-RAG`.
3. **Configure & Launch**:
   - Render will parse `render.yaml` and display the three services (`gatekeep-postgres`, `gatekeep-qdrant`, and `gatekeep-rag`).
   - Click **Apply**.
4. **Access the Live Application**:
   - Once the build succeeds, visit your assigned URL (e.g. `https://gatekeep-rag.onrender.com`).
   - The interactive React UI will load directly, and API Swagger docs will be accessible at `/docs`.

## 2. Environment Variables Reference

| Variable | Description | Default / Render Source |
|---|---|---|
| `DATABASE_URL` | PostgreSQL connection string | Injected from `gatekeep-postgres` |
| `MIGRATION_DATABASE_URL` | Migration connection string (owner) | Injected from `gatekeep-postgres` |
| `QDRANT_URL` | URL of the Qdrant instance | Injected as `http://gatekeep-qdrant:6333` |
| `JWT_SECRET` | Secret key for signing HS256 auth tokens | Auto-generated by Render blueprint |
| `PERSISTENCE_BACKEND` | Storage backend for metadata and ACLs | `postgres` |
| `VECTOR_BACKEND` | Storage backend for chunk embeddings | `qdrant` |
| `RUN_REAL_STACK` | Flag to enable live service integration | `1` |
| `EMBEDDING_MODEL` | Local sentence-transformers model | `all-MiniLM-L6-v2` |
| `PORT` | HTTP listener port | Set dynamically by Render (`10000`) |

## 3. Alternative: Deploy via Docker Compose (VPS / Cloud VM)

To deploy on any virtual machine or cloud server (AWS EC2, DigitalOcean, Hetzner, etc.):

```bash
# 1. Clone repository
git clone https://github.com/saturn-16/GateKeep-RAG.git
cd GateKeep-RAG

# 2. Configure environment
cp .env.example .env
# Set a strong JWT_SECRET in .env

# 3. Build and launch container stack
docker compose up -d --build

# 4. Verify service health
docker compose ps
curl http://localhost:8000/healthz
```

## 4. Production Security Hardening Checklist

Before exposing the service to external production traffic:

- [ ] **Rotate Demo Passwords**: Update passwords for seeded demo accounts (`alice`, `bob`, `dave`, etc.) or re-seed using custom credentials.
- [ ] **Database Credentials**: Replace default container passwords (`gatekeep:gatekeep`) with strong passwords stored in a secret manager.
- [ ] **CORS Configuration**: Restrict allowed CORS origins in `src/app/main.py` if serving the frontend from a separate custom domain.
- [ ] **Rate Limiting**: Configure production rate limits in `.env` based on expected traffic volume.
